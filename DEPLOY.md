# Деплой бастиона на сервер

Бастион живёт на своём домене, например `bastion.example.com`. Ставить его можно на отдельный сервер или на сервер с одним из сайтов Delivest.

## 0. Что нужно заранее

- Сервер с Ubuntu или Debian и root-доступом.
- Домен для бастиона, у которого A-запись указывает на IP сервера. Проверить: `dig +short bastion.example.com`.
- Открытые порты 80 и 443. Если включён ufw: `ufw allow 'Nginx Full'`.

## 1. Подготовить сервер

Если на сервере уже стоит Delivest, этот шаг пропустите: всё нужное уже установлено.

```bash
apt update && apt upgrade -y
curl -fsSL https://get.docker.com | sh
apt install -y nginx certbot python3-certbot-nginx
```

## 2. Скачать проект

```bash
git clone https://github.com/ShafranovKirill/delivest-bastion.git /root/bastion
cd /root/bastion
cp .env.example .env
```

## 3. Заполнить `.env`

Сгенерируйте секреты:

```bash
openssl rand -base64 48   # SECRET_KEY_BASE
openssl rand -hex 16      # DB_PASSWORD
openssl rand -hex 32      # AGENT_TOKEN
openssl rand -hex 16      # S3_ACCESS_KEY
openssl rand -hex 32      # S3_SECRET_KEY
```

```bash
nano .env
```

| Переменная | Что указать |
| --- | --- |
| `PHX_HOST` | домен бастиона без `https://`: `bastion.example.com` |
| `BASTION_PORT` | свободный локальный порт, например `4100`. Если на сервере есть Delivest, порт должен отличаться от его `GATEWAY_PORT` |
| `LETSENCRYPT_EMAIL` | почта для писем Let's Encrypt о сертификате |
| `SECRET_KEY_BASE` | сгенерированное значение |
| `DB_PASSWORD` | сгенерированный пароль базы |
| `ADMIN_LOGIN` / `ADMIN_PASSWORD` | логин и пароль для входа в панель |
| `AGENT_TOKEN` | общий токен агентов, его же указывают в Delivest как `BASTION_TOKEN` |
| `S3_ACCESS_KEY` / `S3_SECRET_KEY` | сгенерированные ключи хранилища бэкапов |
| `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID` | Telegram-бот и уведомления, можно оставить пустыми (шаг 7) |

## 4. Подключить nginx и получить сертификат

```bash
./deploy/host-nginx.sh
```

Скрипт создаёт сайт nginx для `PHX_HOST`, получает сертификат Let's Encrypt и включает HTTPS с поддержкой websocket. Запускать его повторно безопасно.

## 5. Запустить

```bash
docker compose pull
docker compose up -d
docker compose logs bastion --tail 20
```

Миграции применяются сами при каждом старте. Откройте `https://bastion.example.com` и войдите с `ADMIN_LOGIN` и `ADMIN_PASSWORD`.

## 6. Подключить сайты Delivest

На каждом сервере с Delivest допишите в `.env` сайта:

```
BASTION_URL=wss://bastion.example.com
BASTION_TOKEN=<AGENT_TOKEN из .env бастиона>
INSTANCE_NAME=Название сети
```

Затем в папке сайта:

```bash
docker compose pull
docker compose up -d
docker logs delivest_agent --tail 20
```

В логах агента должно быть `joined bastion`, а сайт через несколько секунд появится в панели. Если `COMPOSE_PROJECT_NAME` у сайта не `delivest`, контейнер называется `<COMPOSE_PROJECT_NAME>_agent`.

## 7. Telegram-бот

1. Создайте бота у [@BotFather](https://t.me/BotFather) и скопируйте токен.
2. Впишите `TELEGRAM_BOT_TOKEN` в `.env` бастиона и выполните `docker compose up -d`.
3. Напишите боту `/start` в личке или добавьте его в группу и напишите там. Бот ответит id чата.
4. Впишите этот id в `TELEGRAM_CHAT_ID` и снова выполните `docker compose up -d`.

Бот отвечает только в чате из `TELEGRAM_CHAT_ID`. Если это группа, управлять сайтами могут все её участники.

Что умеет бот:

- `/menu`: сводка по всем сетям и кнопки.
- `/sites`: список сетей. По кнопке сети откроются её контейнеры, проверки, диск и аптайм, а также кнопки «Обновить сайт», «Перезапустить», «Включить», «Выключить», «Логи» и «Простой». Обновление, перезапуск и выключение нужно подтвердить.
- `/downtime`: аптайм и простой каждой сети за 24 часа, 7 и 30 дней.

Бот сам пишет, когда сайт перестаёт отвечать, когда агент пропадает со связи дольше чем на 2 минуты и когда всё снова работает (с длительностью простоя). Ещё он сообщает, чем закончились обновление, перезапуск, включение, выключение, запись `.env` и восстановление из бэкапа, кто бы их ни запустил. Пока команда выполняется, 2 минуты после включения или перезапуска и пока сайт выключен по плану, тревог о простое нет.

Отдельно бот пишет:

- когда процессор или память сервера держатся выше 90% 5 минут подряд и когда нагрузка вернулась в норму;
- когда заказ не ушёл во Frontpad или висит в очереди на отправку дольше 5 минут, с номером заказа, филиалом и ошибкой;
- когда бэкап сайта не сделан.

Бот получает сообщения через long polling, поэтому вебхук и открытый порт ему не нужны. Если раньше у бота был вебхук, бастион снимет его при старте.

## 8. Бэкапы сайтов

Каждый день в 00:00 UTC (03:00 МСК) бастион просит агента каждого сайта снять дамп базы и принимает файл в своё хранилище SeaweedFS (контейнер `bastion_s3`, том `s3_data`). Хранилище наружу не открыто, агент загружает файл через `https://<домен бастиона>/agent/backups/...` по одноразовому токену. Для каждого сайта хранятся последние 7 бэкапов, логи сайта в них не входят.

На странице сайта видны бэкапы и кнопки «Сделать бэкап», «Скачать», «Восстановить», а также «Развернуть сюда бэкап другой сети» для переноса на новый сервер. Если бэкап не сделан, бот пишет в Telegram, результат восстановления он тоже присылает.

Бэкапы сайта, удалённого из бастиона, остаются и их можно развернуть. Место на диске: примерно 10–50 МБ на копию для сети со 100 заказами в день.

Чтобы работали бэкапы, нагрузка и тревоги по заказам, сайту нужен свежий агент. Бастион не обновляет агента сам, поэтому на каждом сервере сайта один раз выполните:

```bash
docker compose pull agent
docker compose up -d agent
```

## Обновление бастиона

```bash
cd /root/bastion
git pull
docker compose pull
docker compose up -d
```

Если в обновлении менялся `deploy/host-nginx.sh`, запустите его снова: `./deploy/host-nginx.sh`. Для бэкапов он снимает ограничение на размер загрузки по адресу `/agent/backups/`.

## Бэкап базы бастиона

```bash
docker exec bastion_postgres pg_dump -U postgres bastion | gzip > /root/bastion-$(date +%F).sql.gz
```

В базе хранятся список экземпляров, история команд и список бэкапов. Если её потерять, агенты зарегистрируются заново сами, а файлы бэкапов останутся в томе `s3_data`, но пропадут из списка в панели.

## Если что-то не работает

| Симптом | Где смотреть |
| --- | --- |
| панель не открывается | `docker compose ps`, `docker compose logs bastion --tail 50`, `nginx -t` |
| certbot не получает сертификат | DNS указывает на сервер? открыт порт 80? |
| сайт не появляется в панели | `docker logs delivest_agent`: совпадает ли `BASTION_TOKEN` с `AGENT_TOKEN`, начинается ли `BASTION_URL` с `wss://` |
| агент пишет `bastion disconnected` | доступен ли домен бастиона с сервера сайта: `curl -I https://bastion.example.com` |
| экземпляр «Не на связи», хотя сайт работает | `docker compose ps` в папке сайта: запущен ли контейнер `agent` |
