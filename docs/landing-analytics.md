# Лендинг и аналитика

## Что работает без Яндекса

Бастион принимает и сохраняет заявки независимо от переключателей аналитики. При включённом собственном счётчике лендинг отправляет `page_view` и действия. Просмотры — события загрузки страницы, визиты — различные идентификаторы 30-минутных сессий с просмотром. Это не точное число физических людей: блокировка JavaScript, разные устройства, очистка хранилища и боты влияют на результат. Счётчик не восстанавливает посещения до его установки.

Источник, UTM-поля и `yclid` сохраняются с сессией и заявкой. Персональные поля заявки не отправляются в Метрику или события аналитики. Referrer передаётся без query string. На лендинге нет секретов Яндекса.

## Контракт

Все вызовы браузера идут на домен лендинга. Nginx проксирует только `/api/landing/` на Бастион по общей сети Compose. Административные страницы через этот прокси не публикуются.

- `GET /api/landing/config` — только `tracking_enabled`, `metrika_enabled`, `metrika_counter_id`.
- `POST /api/landing/events` — `event_id`, `session_id`, `event`, `path` и поля атрибуции.
- `POST /api/landing/leads` — `request_id`, `session_id`, `name`, `contact`, `intent`, `website` и поля атрибуции. Имя необязательно. Контакт обязателен.
- Атрибуция: `utm_source`, `utm_medium`, `utm_campaign`, `utm_content`, `utm_term`, `yclid`, `referrer`.

Повтор запроса с тем же идентификатором не создаёт ещё одну запись. Успех формы определяется ответом `ok: true, saved: true`. Для honeypot возвращается `saved: false`, событие успешной заявки не отправляется. После сохранения уведомление ставится в очередь Oban: недоступность Telegram не теряет заявку. Получателей задают в настройках лендинга; при пустом списке используется основной чат Бастиона.

## Подключение Яндекса

1. Создать отдельный счётчик Метрики для `https://delivest.ru`, задать московский часовой пояс и внести ID в Бастион. Собственная аналитика и Метрика включаются независимо.
2. Создать в Метрике JavaScript-цели с точными идентификаторами: `lead_open`, `lead_success`, `contact_telegram`, `contact_vk`, `contact_phone`. Открытие формы и переход в мессенджер не равны заявке.
3. Включить Метрику в настройках лендинга. Вебвизор и карты поведения в выбранный базовый объём не входят и отключены в коде счётчика.
4. В настройках кампаний Директа указать этот счётчик. Сохранять `yclid` при редиректах. Для источников рекомендуется `utm_source=yandex&utm_medium=cpc`, а `utm_campaign` — числовой ID кампании.
5. Для серверной сводки указать OAuth-токен с разрешениями чтения статистики Метрики и Директа, логин кабинета и ID кампаний лендинга. Токен не возвращается в форму; пустой ввод сохраняет прежний. Это ручное подключение токена; автоматическая выдача/обновление токена OAuth пока не реализована. Токен хранится в БД Бастиона, поэтому резервные копии БД также содержат его.
6. Обновить сводку в Бастионе. Проверить дату, выбранные кампании и состояние подключения. До первого успешного запроса отображается отсутствие данных; ошибка не заменяет прошлую успешную статистику нулями.

Расходы Директа относятся к валюте рекламного кабинета, без НДС. Цена заявки имеет смысл только для сопоставимого периода и рекламных источников; органические обращения в знаменатель не включаются. Это оценка по меткам собственной системы, она может отличаться от атрибуции Яндекса. Источники, не содержащие рекламные метки, нельзя автоматически признать рекламными.

Официальные источники: [связка Директа и Метрики](https://yandex.ru/support/metrica/ru/general/direct), [формат отчёта Директа](https://yandex.ru/dev/direct/doc/ru/spec), [пример расходов и кликов](https://yandex.ru/dev/direct/doc/ru/example).
