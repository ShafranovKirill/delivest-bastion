# Переход к общему репозиторию

Это инструкция для отдельного согласованного обновления production. Локальное объединение не переносит работающие сайты и не изменяет удалённые репозитории.

1. Сохранить текущие ревизии Бастиона и лендинга, конфигурацию host nginx, `.env` и резервную копию БД. Проверить восстановление по принятой процедуре. Не коммитить секреты.
2. Получить проверенную ветку общего репозитория. Источник — прежний репозиторий `delivest-bastion`; лендинг находится в `landing/`, сервер — в `bastion/`. Старый репозиторий лендинга пока не удалять и не архивировать.
3. Сохранить прежний Compose project name и пути существующих томов. Проверить `docker compose config` и фактические имена томов до запуска. Команда `down -v` недопустима. Не поднимать параллельно стек с теми же `container_name`.
4. Перенести настройки в корневой `.env`, сохранив секреты и текущие значения Бастиона. Добавить `DOMAIN=delivest.ru`, `LANDING_PORT` и при необходимости почту TLS. Прежний отдельный `lead`-сервис заменяется обработчиком Бастиона. Его Telegram chat ID можно указать в настройках лендинга; бот использует серверный токен Бастиона.
5. Собрать и обновить только Бастион. Миграция создаёт отдельные таблицы лендинга. Проверить вход, инстансы, агентов, бэкапы, прежние уведомления. В новой вкладке указать адрес лендинга, настройки учёта и получателей заявок.
6. После готовности API обновить лендинг на общей сети. Отключить прежний экземпляр лендинга перед использованием того же порта/имени контейнера. Проверить главную страницу, `/api/landing/config`, запись просмотров и реальную тестовую заявку. Проверить, что админские страницы Бастиона не доступны через домен лендинга.
7. Подключить Метрику и Директ, проверить одну цель и реальный отчёт. Сверить период и список кампаний. Подключение к реальному кабинету требует собственных реквизитов владельца; локальные тесты не подтверждают доступ к нему.

## Обновления и откат

Приложения выпускаются независимо. Из корня: `docker compose up -d --build --no-deps bastion` либо `docker compose --profile landing up -d --build --no-deps landing`. Не используйте обновление всего стека ради текста лендинга.

При откате сохранить текущую БД, затем вернуть прежние образы и nginx-конфигурацию. Новые таблицы не удалять автоматически. Старый лендинг с прежним сервисом заявок можно вернуть отдельно, пока его копия сохранена. Старые обращения из Telegram автоматически в базу не импортируются. Историческая посещаемость до установки счётчика недоступна.
